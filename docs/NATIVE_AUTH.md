# Lean native authentication (source candidate)

`@nlabs/metropolisjs/api` exports `createNativeApi` and the structural `GraphqlBinding`, compatible with Rip-Hunter 3.2.1's public `/graphql` `graphqlRequest`. Inject that installed binding; no legacy root transport imports, retries, offline queue, lifecycle hook or platform request implementation is installed by this module. Supply an explicit HTTPS endpoint and request deadline in milliseconds (zero disables). Authentication opts out of authenticated preflight and preserves transport errors. Protected calls require a configured preflight that returns the controller's current token.

`@nlabs/metropolisjs/native-auth` exports `createNativeAuthController`, `NativeAuthError`, `parseCredentialEnvelope` and their public types. Configuration requires `mode: 'hosted'`, a fixed environment, a public Arkham `FluxFramework`, and storage/caches supplied by thin native bindings. Local POC is a separate existing application path: this controller never synthesizes credentials or migrates POC data. Create a new scoped controller/namespace for environment changes, dispose the old controller before releasing its binding, and never share namespaces across environments.

The **new strict hosted GraphQL profile** must implement:

- `users.signIn(user: UserInput!)` and `users.refreshSession(token: String!)`, returning exactly `schemaVersion environment token userId username issued expires sid`.
- `users.signOut(token: String!): Boolean!`, returning true only after successful awaited family revocation.

These additions are not the legacy root schema: its `signOut` has no token argument and its SessionToken omits the new envelope fields. Real Lambda schema composition remains a separate adoption gate. The controller submits named documents `MetropolisSignIn`, `MetropolisRefresh`, and `MetropolisSignOut`, with no client lifetime override. Envelope version is 1; metadata is milliseconds, JWT iat/exp are numeric finite safe integer epoch seconds (strict hints reject strings, fractional values and the millisecond range). Strict allowlisted shape, bounds, at most 15-minute lifetime, a maximum 30-second future issue allowance, agreement within one JWT second, and conservative expiry are validated. The additive public session `parseStrictJwtTimeHints` reuses the existing owned decoder; legacy `parseJwtExpiryMs`/`parseJwtIssuedMs` retain their coercion/millisecond behavior. JWT decoding is an untrusted time hint and does not establish a verified signature, server identity, or revocation status.

`NativeSessionPersistence` is an explicit rejecting promise port. Compose secure whole-envelope writes/reads/deletes and nonsecret signout markers through separate **Arkham-owned ordered NativeStorage instances**, not a local queue. Require the reviewed immediate-state Core behavior (3.31.17-architecture.1 candidate) and NativeStorage's strict injected backend; installed Kurupt Core 3.31.15 remains insufficient. Secure availability must be checked through the actual platform adapter, with no hosted insecure fallback. Scope namespaces by environment and retain whole-envelope atomicity; use SecureStore's WHEN_UNLOCKED_THIS_DEVICE_ONLY policy. Secure credentials never enter Flux. Ordinary persisted state must exclude credentials/passwords/wrappers. Flux publishes only status, environment, generation, userId, username, sid and expiry.

Sign-in invalidates the active account and synchronously starts marker/deletion cleanup before its first awaited publish. This deliberately leaves a failed account switch signed out and prevents an older queued write surviving a newer failed sign-in. A successful operation awaits secure commit, then marker removal, then publishes current state before its authenticated event. Visibility and commits are generation-gated. A controller-owned authentication admission barrier retains all already-started cleanup completion across superseded generations; later restore/sign-in cannot read or commit until it settles. This barrier composes the Arkham queues and implements no generic storage queue. A new successful cleanup can recover an earlier failed barrier. The synchronous required `invalidateAccount` callback removes application-owned active cache/outbox bindings before notifications; durable saves and queue algorithms remain their respective domain owners.

Renewal uses the existing shared millisecond decision and per-generation single-flight. Healthy tokens return immediately; renewal starts within five minutes of expiry, validates same user/sid/environment, and securely commits before publishing. Only network/timeout/abort failures retain an unchanged, still-valid token. Invalid/revoked/expired credentials clear state and durable cleanup is attempted. Expired credentials never reach renewal. Restore checks any persisted marker before secure reads; malformed/wrong-environment/expired envelopes cannot restore authentication. Restoration permits local identity continuity, not online verification.

Sign-out synchronously advances generation, removes local credentials/cache/outbox binding and invokes both owned cleanup queues before any awaited publish/listener. It completes durable cleanup and captured-family revocation even if a newer restore/sign-in supersedes its visible generation. Anonymous events describe local state; the returned promise carries durable completion. Either successful path makes restart suppression durable; if both fail `NativeAuthError.code` is `durable_cleanup` while local state remains anonymous. Remote revoke is best effort and returns `remote: 'may_remain_active'` on failure/false acknowledgement; the family may remain active until its server absolute limit and issued bearers expire within the bounded lifetime. `dispose()` waits for signout cleanup and prevents new work; injected transport owns deadline/cancellation, and the controller makes no retry or remote cancellation guarantee.

Source tests and isolated public contracts qualify implementation only. Frozen archive/profile review, actual consumer manifest/lock installation and peer compatibility, strict hosted Lambda schema/managed identity, networking, and physical iOS/Android secure-storage acceptance remain open. Legacy notification/persona/React/browser peers are retained; an installable lean distribution profile must be reviewed rather than silently stripping them.
